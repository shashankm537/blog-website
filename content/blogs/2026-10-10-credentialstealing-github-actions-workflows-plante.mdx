## Malicious Code Infiltrates Thousands of GitHub Repositories, Stealing Sensitive Secrets

A sophisticated campaign is secretly injecting malicious code into open-source projects on GitHub, with researchers uncovering over 340 repositories compromised in a recent wave. The attack, linked to a previously identified threat actor, exploits compromised developer accounts to push harmful workflows that pilfer sensitive credentials.

### How the Attack Unfolds

The GhostAction campaign, first identified last year, has resurfaced with a renewed focus on stealing valuable secrets. Researchers at StepSecurity observed an attacker gaining access to high-profile open-source maintainer accounts. Using the compromised credentials of the creator of the popular game engine pyxel, the attacker inserted a malicious workflow into 27 repositories. Hours later, the account associated with Uber's athenadriver was similarly used to distribute the same harmful code to an additional 318 repositories in a matter of minutes.

### The "Security Audit" Deception

The injected malicious code is disguised as a legitimate "Security Audit" or "GitHub Actions Security" workflow. These deceptive files are designed to silently exfiltrate sensitive data from repositories to a specific IP address. The information stolen includes critical CI/CD secrets, cloud provider credentials, and API keys for popular services like AWS, Anthropic, OpenAI, and even tokens for GitHub and GitLab themselves. This broad access to secrets allows attackers to potentially gain control over infrastructure, impersonate legitimate users, and cause significant damage.

### What To Watch

Cybersecurity firms are actively tracking the GhostAction campaign and advising developers to scrutinize their GitHub repositories for any unfamiliar workflows. The ongoing nature of these attacks highlights the persistent threat to the open-source supply chain and the critical importance of robust credential management and security practices for all developers.
